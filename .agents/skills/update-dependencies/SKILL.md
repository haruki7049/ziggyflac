# Update Workflow: Nix Inputs, Zig Version, and Test Fixtures

`ziggyflac` has no external Zig package dependencies (`dependencies = .{}` in `build.zig.zon`). The following areas still require a coordinated update.

## Nix inputs (`flake.lock`)

1. Run `nix flake update`.
1. Run `treefmt --fail-on-change`, `zig build`, and `zig build test` (inside `nix develop` or via direnv).
1. Commit with `build(flake.lock): nix flake update`.

## Zig package dependencies (`.deps.nix`)

`flake.nix` links `./.deps.nix` (generated by `zon2nix`) as `zig-pkg` for the Nix package build. If a Zig dependency is ever added to `build.zig.zon` (only with explicit user approval):

1. Run `zon2nix > .deps.nix` inside `nix develop`.
1. Run `zig build`, `zig build test`, and `nix build` to confirm both builds still work.
1. Commit `build.zig.zon` and `.deps.nix` together.

## Zig version bumps

When changing the Zig version, update all of the following together:

- `minimum_zig_version` in `build.zig.zon`
- `pkgs.zig_0_XX` in `flake.nix` (both `nativeBuildInputs` and `settings.formatter.zig.command`)
- The target Zig version noted in `AGENTS.md`
- Any Zig version pinned in `.github/workflows/` (once CI exists)

## Adding or updating FLAC test fixtures

1. Prefer small, purpose-built FLAC files (e.g. a few frames generated with `flac` or `sox`) over real recordings, and record how each fixture was generated.
1. If large binary fixtures become necessary, discuss introducing Git LFS (`.gitattributes` + `.lfsconfig`) with the user before adding them.
1. Adding, removing, or replacing binary fixtures is an irreversible-adjacent operation (see `.agents/skills/irreversible/SKILL.md`) — confirm with the user before committing large or replaced fixtures.
1. Run `zig build test` to confirm the new fixture is parsed as expected.
